# Boring Code Oath

We should strive to write code that can be considered boring and plain looking. No clever tricks, code that is simple to understand because is straight-foward. Doing this reduces the number of surprises and effort to perform modifications.

> *Boring code:
- is consistent
- is not clever
- is easily understandable
- makes locating features easy
- adheres to Principle of Least Surprise (things do what I assume they would)
- takes a minimal amount of effort to change
- uses the right tool (paradigm, language) for the job*
